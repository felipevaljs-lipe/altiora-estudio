# Lead capture backend (Lex V2 → Lambda → DynamoDB)

When a visitor completes the chatbot flow (`SolicitarServicio` intent), Amazon
Lex invokes a Lambda that saves the lead to DynamoDB and optionally emails your
team. The Angular frontend needs **no changes** — it already sends everything
to Lex.

```
Browser → Amazon Lex V2 → (fulfillment) Lambda → DynamoDB
                                              └→ SES email (optional)
```

## Files

| File | Purpose |
|------|---------|
| `lambda/index.mjs` | The fulfillment function (Node.js 20, ESM) |
| `lambda-execution-policy.json` | IAM policy for the Lambda role (DynamoDB + SES + logs) |
| `setup.sh` | One-shot script: table + role + Lambda |

## 1. Provision the backend

From the project root, with AWS CLI v2 configured for account `229975483756`:

```bash
bash aws/setup.sh
```

This creates:
- DynamoDB table `EstudioNubeLeads` (partition key `id`, on-demand billing)
- IAM role `EstudioNubeLeadLambdaRole`
- Lambda `EstudioNubeLeadFulfillment`
- Permission for Lex to invoke the Lambda

## 2. Attach the Lambda to the bot (console)

1. **Lex console → your bot → Aliases → `TestBotAlias`** (the alias behind
   `TSTALIASID`). Under **Languages → Spanish (…)**, set the **Lambda function**
   to `EstudioNubeLeadFulfillment`, then **Save**.
2. **Bot → Intents → `SolicitarServicio` → Fulfillment**. Expand **"On
   successful fulfillment"** → enable **"Use a Lambda function for
   fulfillment"**. Save the intent.
3. **Build** the bot.

> Lex V2 only calls the Lambda for an alias that has a Lambda configured *and*
> for intents where the fulfillment code hook is enabled — both steps are
> required.

## 3. Test

Open the site, complete the chat (service → name → email). The closing message
is now generated by the Lambda. Verify the row landed:

```bash
aws dynamodb scan --region us-east-1 --table-name EstudioNubeLeads \
  --filter-expression "attribute_not_exists(kind)" \
  --query "Items[].{nombre:nombre.S,email:email.S,servicio:servicio.S,createdAt:createdAt.S}" \
  --output table
```

## 4. (Optional) Email notifications via SES

1. Verify a sender identity in SES (e.g. `hola@estudionube.com`), and — while
   your account is in the SES sandbox — verify the recipient too.
2. Add env vars to the Lambda:

```bash
aws lambda update-function-configuration \
  --region us-east-1 \
  --function-name EstudioNubeLeadFulfillment \
  --environment "Variables={LEADS_TABLE=EstudioNubeLeads,SES_FROM=hola@estudionube.com,SES_TO=hola@estudionube.com}"
```

The Lambda skips email automatically if `SES_FROM`/`SES_TO` are unset.

## Viewing leads

- **Quick:** the `aws dynamodb scan` command above.
- **Console:** DynamoDB → Tables → `EstudioNubeLeads` → Explore items.

> The table also holds short-lived rate-limit guard rows (`id` starting with
> `rl#`, `kind: "ratelimit"`). Filter them out when reading real leads, e.g.
> add `--filter-expression "attribute_not_exists(kind)"` to the scan.

## Cost

All within or near the AWS Free Tier for low volume: DynamoDB on-demand (pay per
request), Lambda (1M free requests/month), SES (62k free/month from Lambda).
